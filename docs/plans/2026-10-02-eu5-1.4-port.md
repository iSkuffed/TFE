# Porting TFE to EU5 1.4

Static analysis on 2026-10-02 against the installed `1.4-open-beta` (build 2026-09-29, branch `ud009/release/next`,
clausewitz 2026.39.0). Nothing was launched in game, so every "in game" claim below is inferred from files, logs and the
web. Mod last green on 1.3.11; `.metadata/metadata.json` still says `supported_game_version: "1.3.*"`.

## Timeline

- Open beta opened 2026-10-01; official release **2026-10-28** (Steam news, Oct 1: store.steampowered.com/news/app/3450310/view/1845383656381246).
- Earlier betas ran 30 (1.1) and 35 (1.3) days; 1.3 got weekly beta patches and its last beta build became the release.
  Expect 1.4.x betas to keep changing until the 28th, with no announced content freeze.
- Plan: do the structural fixes now; do the vanilla-copy resyncs against the last beta build.

## Root cause of "map is vanilla 1337"

1.4 replaced `main_menu/setup/start/` with bookmarks. Vanilla now has `main_menu/common/bookmarks/00_bookmarks.txt`:
`bookmark_1337 = { start_date = 1337.4.1  end_date = 1836.12.31  setup_folder = "setup/1337" }`, plus `setup/1337/`,
`setup/1658/` (a stub of one-line `include = "setup/1337/NN_x"` files; its 1658 bookmark is commented out) and
`setup/templates/`. TFE writes its whole start to `main_menu/setup/start/` (21 files) and defines no bookmark, so the
engine never reads it. Further consequences:

- The bookmark's `start_date` stamps the game date (vanilla comment in `00_bookmarks.txt`), so `START_DATE = 395.1.18` in
  `loading_screen/common/defines/tfe_defines.txt` is probably ignored. Untested.
- Every vanilla scenario now carries `bookmark = bookmark_1337`; `main_menu/common/scenarios/00_scenarios.txt` (ours) has none.
- Vanilla's setup folder has `02_core`, `08_institutions`, `19_diseases`, `22_situations`, which TFE never had (merged by
  filename from vanilla before). A TFE setup folder needs them, e.g. as `include = "setup/1337/02_core"`.
- eu5.exe strings include "Bookmark {} has no setup_folder set" and "setup_folder ... contains no .txt files".
- The Bronze Era total conversion ported this in a day: a bookmarks file plus renaming `setup/start/*` (github.com/vador03/Bronze-Era/pull/118).

Not verified: whether a mod `setup/<folder>` merges with vanilla's by filename, and whether the old `start/` is read
as a fallback (no string evidence that it is).

## Open question: the very long load

The user's TFE-on 1.4 new-game attempt was very slow and ended on 1337. Its log no longer exists (`logs/` is overwritten
per launch; the later session was a Goryeo save load, and `crashes/` holds only 1.3 and vanilla-1.4 runs). Nothing
static explains the slowness. Needs one timed 1.4 launch with TFE enabled, **only when the user says so**. Playset "1.1"
is empty on purpose (used to play 1.4 with a friend); TFE is in no playset, so enable it in a playset first.
Log error rotation (1 MB x 5 files) destroyed the early data-load errors last time: copy `logs/` out soon after the
launch, and do not trust a count above ~5 MB.

## What is fine

- Map data: 28573 locations in the committed templates, in vanilla 1.4 and in the regenerated file; none missing, none new.
  `locations.png` and `nodes.dat` are unchanged. Hierarchy ownership regenerates byte-identical.
- Every key in our country entries (`10_countries`, `04`, `05`, `06`, `12`) exists in vanilla 1.4's; no new required keys.
- All prefixed references (`advance_type:`, `government_reform:`, `subject_type:`, `culture:`, `religion:` ...) resolve; 19 `REPLACE:` targets still exist.
- `script/run.py` outputs, `place_names.py` and `25_area_preferences.txt` regenerate with no diff.
- `theodosian_walls` block still matches vanilla; `00_loading_screens.txt`, `water.settings`, `tfe_languages.txt` hashes OK.
- `mod/TFE/.metadata` only warns on version mismatch; nothing in the logs shows `supported_game_version` blocking a mod.

## Unknowns

- 12021 vanilla files carry an Oct 1 mtime (in_game 6111, main_menu 4080, loading_screen 1830), so mtime means "touched",
  not "changed". Registries we extend were mostly touched: advances 165/227, building_types 43/46, laws 24/31,
  cultures 31/53, international_organizations 28/35, subject_types 18/19. No 1.3 baseline exists to tell content change
  from restamp.
- Removed or renamed effects, triggers, modifiers, on_actions: not measurable without regenerated docs. Do the
  `script_docs` run first thing in the next game session, keep a copy of the old docs (`docs/*.log`, 2026-09-26) and diff.
- Official 1.4 patch notes were not readable (JS-gated forum). Known from dev diaries (Tinto Talks 118-125): complacency
  removed and Political Influence added (the Bronze Era port saw `modifier:has_complacency_effects`, `monthly_complacency`
  disappear from `auto_modifiers/country.txt`); ticks are daily only, speeds 6 and 7 removed (anything on hourly pulses);
  laws, road builder and peace-treaty UI passes (the `location_window.gui` was rewritten, ~4300 lines in Bronze Era's port);
  new Decisions system open to modders, Expeditions, Cardinals, Crusade/Jihad rework, Religious Orders, tariffs, canals,
  Trade Orders, inheritance contracts and betrothals, estate private armies, food-driven pop growth, "Discriminated"
  culture acceptance renamed "Ignored", mercenary changes, mod-manager dependency auto-reorder and checksum alerts.
- `main_menu/common/coat_of_arms/coat_of_arms/tfe_countries.txt` redefines `ALM`, `SAX`, `ASK`, `SHL`, `SIL`, `RMN`
  without `REPLACE:`; a duplicate-key hazard that may predate 1.4.
- 1.4's new mechanics (Decisions, Expeditions, Cardinals, Political Influence ...) are an opportunity for TFE: check
  them against `RoadMap.md` once the port lands.

## Status, 2026-10-03 (PR #88, branch `1.4`)

Done. The 395 map loads on 1.4 in about 90 s. An observer game ran from 395 to 434 with no crash. Probes in 434 found
the Decline of the West and the Hunnic Storm active, peoples migrating and settling, and Gildo's revolt fired.
Script docs were regenerated on 1.4 and `api.py` rebuilt from them; pyright and `lint_script.py` are clean.

1.4 removed only `add/set_complacency`, `add_trust`, the `complacency*` triggers, `has_ai_disposition_toward_player`,
8 modifiers (complacency, trust, `local_food_decay_modifier` ...) and 2 on_actions. The mod used none of them.

Changes made beyond the table above:
- `area_average_control` now needs a country: `"area_average_control(scope:actor)" < 0.3`. The docs still list it
  bare.
- Axum and Nobatia set `type = monarchy` (1.4's `subsaharan_monarchy` template no longer does).
- New 1.4 load warnings fixed: `io_opinion_tfe_barbaricum`/`_hunnic_yoke` biases, plus the IO
  `diplomatic_status_*`/`*_list_who_tt` loc and `AM_`/`LEAD_tfe_foederati`.

Both crashes in testing came from hot reload (files rewritten while the game ran), not from the mod.

Left as they are (noise, no crash):
- About 38k startup errors from vanilla tags with no government.
- Vanilla HRE and 1337-character scripts that find no target.
- Characters with more ruler traits than 1.4 expects.

Still open:
- Settled, not open: the colonial-charter gate is dropped for good (in 395 Rome borders no unclaimed land), and
  bookmark card art only matters once a second start exists (with one bookmark, New Game skips the picker).
- Mining 1.4's mechanics (Decisions especially) for RoadMap items.
